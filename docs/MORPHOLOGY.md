# Morphology — Algorithmic System

Morphology in lexFlex is **algorithmic, not tabular**. Word forms are generated by applying rules to stems, not looked up in hardcoded tables. Exceptions are explicitly listed; everything else follows paradigm rules.

**2026-07-10 Iterative Audit (docs updated in parallel with ERRORS.MD and code review):**
While the philosophy is correct, implementation has significant hardcoded remnants (detailed in lexFlex/ERRORS.MD — see the new "Full Cross-Language (PL + EN) Non-Algorithmic Elements + Linguistic Theory Gaps Audit" section for the exhaustive enumerated list with file:line quotes):
- Degree for irregular comparatives (lepszy, większy...) uses Rust match lists + parser heuristics instead of RON.
- "jabłko" gen.pl patch is a specific if in generator, not a rule.
- Article phonetics (a/an) live in generator code with simplistic checks + cross-lang name hacks.
- Gender inference and paradigm selection mix code ifs with data.
- Passive/verb forms have ending lists and irregular matches.
- Parsers still use crude ends_with + matches! for degree/person before (or instead of) full `reverse_to_stem` + `analyze_via_paradigms`.
- No systematic suppletive or lemma-linked exception tables.

**Required low-level engines (see full list in ERRORS.MD):**
- Bidirectional Stemmer/Analyzer (make analyze_via_paradigms + reverse primary path).
- PhonologyEngine (separate from morph; phonetic classes for articles + alternations).
- Suppletion/Exception engine + richer RON (Prefix, SuppletiveStem, PhoneticInitial conditions).

**RON extensions required for "strictly algorithmic"**:
- PhoneticInitial / vowel class feature (lexicon or computed) for article choice.
- Suppletive stems + Prefix ops (naj-) + better exception linking in paradigms.
- Conditions that allow degree to compose cleanly with case/gender without code bypass.
- Surface variant / mapping data separate from code (to kill the "duży"->"big" etc. contains/replaces).
- Virile / sub-gender composition rules.

See ERRORS.MD (new comprehensive PL+EN + theory gaps section + "Required Low-Level Algorithmic Engines") and UNIFIED... . This file updated concurrently. Next iterations must remove the listed hacks by extending data/rules + minimal inference algos (ending-based where possible). Always re-grep after changes.

## Core Principle

> **Rules generate forms. Exceptions override rules. Paradigms group rules.**

A paradigm is a set of ordered rules that, given a stem + feature bundle, produce the correct surface form. This mirrors how linguists describe morphology — and makes it possible to add new words without writing out every form.

## Architecture

```
FeatureBundle + Lemma
         │
         ▼
┌─────────────────────────┐
│ PARADIGM SELECTOR       │  ← lexicon entry specifies paradigm class
│ "ać" verb paradigm      │
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ RULE ENGINE             │  ← ordered rules: stem modification + suffix
│ Rule 1: stem change     │
│ Rule 2: add suffix      │
│ Rule 3: orthographic fix│
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ EXCEPTION CHECK         │  ← explicit overrides for irregular forms
│ "dać" + 1sg.past → "dałem"│
└────────────┬────────────┘
             ▼
         Surface Form
```

## Paradigm Definition

```rust
struct Paradigm {
    name: String,                          // "verb_ać", "noun_ka"
    applies_to: PartOfSpeech,
    rules: Vec<MorphRule>,                 // ordered rules
    exceptions: Vec<MorphException>,       // explicit overrides
}

struct MorphRule {
    conditions: Vec<Condition>,            // when does this rule apply?
    operations: Vec<Operation>,            // what does it do to the stem?
}

// A condition checks features of the target form
enum Condition {
    TenseIs(Tense),
    AspectIs(Aspect),
    PersonIs(Person),
    NumberIs(Number),
    GenderIs(Gender),
    CaseIs(Case),
    AnimacyIs(Animacy),
    StemEndsWith(String),                  // phonological condition
    StemLength(Min, Max),                  // e.g., for vowel alternations
}

// An operation modifies the stem or adds affixes
enum Operation {
    AddSuffix(String),                     // stem + "łem"
    AddPrefix(String),                     // "nie" + stem (not used in inflection)
    ReplaceSuffix { from: String, to: String },  // "ać" → "am"
    VowelAlternate { from: Vowel, to: Vowel },   // o → ó (Polish vowel shift)
    ConsonantAlternate { from: String, to: String }, // k → c (palatalization)
    Truncate(usize),                       // remove N chars from stem end
    StressShift(usize),                    // not used in PL (fixed penultimate)
}
```

## Polish Noun Declension

### Paradigm Classes

Polish nouns fall into declension classes based on gender and stem ending:

| Class | Gender | Stem Ending | Example |
|-------|--------|-------------|---------|
| `o` | Neuter | -o, -e, -ę | jabłk**o**, mies**e** |
| `a_fem` | Feminine | -a, -i | książk**a**, chwil**a** |
| `a_masc` | Masculine | -a (male persons) | sędzi**a** |
| `consonant_hard` | Masc (inanimate) | hard consonant | bank, dom, stó**ł** |
| `consonant_soft` | Masc (animate) | soft consonant | ko**ń**, li**ś** |
| `consonant_personal` | Masc (personal) | consonant | chłop**ak**, brat |
| `zero_fem` | Feminine | zero ending | noc, miło**ś**ć |

### Noun Paradigm: "o" (Neuter, e.g., "jabłko")

```rust
// data/morphology/pl/noun_paradigms.ron

Paradigm(
    name: "noun_o",
    applies_to: Noun,
    rules: [
        // ─── SINGULAR ──────────────────────────────
        MorphRule(
            conditions: [CaseIs(Nominative), NumberIs(Singular)],
            operations: [],                            // jabłko → jabłko
        ),
        MorphRule(
            conditions: [CaseIs(Genitive), NumberIs(Singular)],
            operations: [
                ReplaceSuffix { from: "o", to: "a" },  // jabłko → jabłka
            ],
        ),
        MorphRule(
            conditions: [CaseIs(Dative), NumberIs(Singular)],
            operations: [
                ReplaceSuffix { from: "o", to: "u" },  // jabłko → jabłku
            ],
        ),
        MorphRule(
            conditions: [CaseIs(Accusative), NumberIs(Singular)],
            operations: [],                            // neuter: ACC = NOM
        ),
        MorphRule(
            conditions: [CaseIs(Instrumental), NumberIs(Singular)],
            operations: [
                ReplaceSuffix { from: "o", to: "em" }, // jabłko → jabłkiem
            ],
        ),
        MorphRule(
            conditions: [CaseIs(Locative), NumberIs(Singular)],
            operations: [
                ReplaceSuffix { from: "o", to: "u" },  // jabłko → jabłku
            ],
        ),
        MorphRule(
            conditions: [CaseIs(Vocative), NumberIs(Singular)],
            operations: [
                ReplaceSuffix { from: "o", to: "o" },  // jabłko → jabłko
            ],
        ),

        // ─── PLURAL ────────────────────────────────
        MorphRule(
            conditions: [CaseIs(Nominative), NumberIs(Plural)],
            operations: [
                ReplaceSuffix { from: "o", to: "a" },  // jabłko → jabłka
            ],
        ),
        MorphRule(
            conditions: [CaseIs(Genitive), NumberIs(Plural)],
            operations: [
                Truncate(1),                           // remove "o"
                AddSuffix("ek"),                       // jabłko → jabłek (with insertion)
                // Note: insertion of "e" is a sub-rule for clusters
            ],
        ),
        // ... Dative, Accusative, Instrumental, Locative for plural
    ],
    exceptions: [],    // "jabłko" has no irregular forms
)
```

## Polish Verb Conjugation

### Paradigm Classes

| Class | Ending | Example | Count |
|-------|--------|---------|-------|
| `ać` | -ać | robi**ć** (→ robi-), czyta**ć** | Most common |
| `eć` | -eć | widzi**eć**, siedzi**eć** | |
| `iść` | -iść | iś**ć**, nieś**ć** | Small class |
| `ować` | -ować | prac**ować**, kup**ować** | Productive (borrowings) |
| `nąć` | -nąć | krzyk**nąć**, znik**nąć** | |
| `irregular` | — | być, mieć, dać, iść, jeść | Handful |

### Verb Paradigm: "ać" (e.g., "czytać" — to read)

```rust
// data/morphology/pl/verb_paradigms.ron

Paradigm(
    name: "verb_ać",
    applies_to: Verb,
    rules: [
        // ─── PRESENT ───────────────────────────────
        // Stem: czyt- (remove -ać)
        
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(First), NumberIs(Singular)],
            operations: [
                Truncate(2),                   // "czytać" → "czyt"
                AddSuffix("am"),               // → "czytam"
            ],
        ),
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(Second), NumberIs(Singular)],
            operations: [
                Truncate(2),
                AddSuffix("asz"),              // → "czytasz"
            ],
        ),
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(Third), NumberIs(Singular)],
            operations: [
                Truncate(2),
                AddSuffix("a"),                // → "czyta"
            ],
        ),
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(First), NumberIs(Plural)],
            operations: [
                Truncate(2),
                AddSuffix("amy"),              // → "czytamy"
            ],
        ),
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(Second), NumberIs(Plural)],
            operations: [
                Truncate(2),
                AddSuffix("acie"),             // → "czytacie"
            ],
        ),
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(Third), NumberIs(Plural)],
            operations: [
                Truncate(2),
                AddSuffix("ają"),              // → "czytają"
            ],
        ),

        // ─── PAST ──────────────────────────────────
        // Past tense in PL encodes gender in singular
        
        // 1sg masculine: "czytałem"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(First), NumberIs(Singular), GenderIs(Masculine)],
            operations: [
                Truncate(2),                   // "czytać" → "czyt"
                AddSuffix("ałem"),             // → "czytałem"
            ],
        ),
        // 1sg feminine: "czytałam"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(First), NumberIs(Singular), GenderIs(Feminine)],
            operations: [
                Truncate(2),
                AddSuffix("ałam"),             // → "czytałam"
            ],
        ),
        // 2sg masculine: "czytałeś"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(Second), NumberIs(Singular), GenderIs(Masculine)],
            operations: [
                Truncate(2),
                AddSuffix("ałeś"),
            ],
        ),
        // 2sg feminine: "czytałaś"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(Second), NumberIs(Singular), GenderIs(Feminine)],
            operations: [
                Truncate(2),
                AddSuffix("ałaś"),
            ],
        ),
        // 3sg masculine: "czytał"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(Third), NumberIs(Singular), GenderIs(Masculine)],
            operations: [
                Truncate(2),
                AddSuffix("ał"),               // → "czytał"
            ],
        ),
        // 3sg feminine: "czytała"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(Third), NumberIs(Singular), GenderIs(Feminine)],
            operations: [
                Truncate(2),
                AddSuffix("ała"),              // → "czytała"
            ],
        ),
        // 3sg neuter: "czytało"
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(Third), NumberIs(Singular), GenderIs(Neuter)],
            operations: [
                Truncate(2),
                AddSuffix("ało"),              // → "czytało"
            ],
        ),
        // 1pl: "czytaliśmy" (virile) / "czytałyśmy" (non-virile)
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(First), NumberIs(Plural), GenderIs(MasculinePersonal)],
            operations: [
                Truncate(2),
                AddSuffix("aliśmy"),
            ],
        ),
        MorphRule(
            conditions: [TenseIs(Past), PersonIs(First), NumberIs(Plural)],
            // non-virile (all other genders in plural)
            operations: [
                Truncate(2),
                AddSuffix("ałyśmy"),
            ],
        ),
        // ... 2pl, 3pl similar
        
        // ─── FUTURE (analytic for imperfective) ────
        // Future imperfective = "będę" + infinitive or past form
        // This is handled at the syntax level, not morphology
        // "będę czytał" or "będę czytać"
        
        // ─── IMPERATIVE ────────────────────────────
        MorphRule(
            conditions: [MoodIs(Imperative), PersonIs(Second), NumberIs(Singular)],
            operations: [
                Truncate(2),
                AddSuffix("aj"),               // → "czytaj!"
            ],
        ),
    ],
    exceptions: [],
)
```

### Irregular Verb: "dać" (to give, perfective)

```rust
Paradigm(
    name: "verb_dać_irreg",
    applies_to: Verb,
    rules: [
        // Present/future (perfective present = future meaning)
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(First), NumberIs(Singular)],
            operations: [
                Truncate(2),                   // "dać" → "d"
                AddSuffix("am"),               // → "dam"
            ],
        ),
        // ... other present forms follow regular-ish pattern
    ],
    exceptions: [
        // Past tense is irregular
        MorphException(
            conditions: [TenseIs(Past), PersonIs(Third), NumberIs(Singular), GenderIs(Masculine)],
            override: "dał",                   // not *"dał" from rules — actually this is regular
            // The irregularity is in the vowel: "dał" vs expected form
        ),
        MorphException(
            conditions: [MoodIs(Imperative), PersonIs(Second), NumberIs(Singular)],
            override: "daj",                   // not *"daj" from "da-" stem
        ),
    ],
)
```

## Adjective Agreement

Adjectives in Polish agree with their noun in **gender, number, and case**. The morphology engine applies the same paradigm-based approach.

### Adjective Paradigm: standard "-y" (e.g., "duży" — big)

```rust
// data/morphology/pl/adj_paradigms.ron

Paradigm(
    name: "adj_y",
    applies_to: Adjective,
    rules: [
        // ─── SINGULAR ──────────────────────────────
        // Masculine
        MorphRule(
            conditions: [GenderIs(Masculine), NumberIs(Singular), CaseIs(Nominative)],
            operations: [],                            // duży → duży
        ),
        MorphRule(
            conditions: [GenderIs(Masculine), NumberIs(Singular), CaseIs(Genitive)],
            operations: [
                ReplaceSuffix { from: "y", to: "ego" },// duży → dużego
            ],
        ),
        MorphRule(
            conditions: [GenderIs(Masculine), NumberIs(Singular), CaseIs(Dative)],
            operations: [
                ReplaceSuffix { from: "y", to: "emu" },// duży → dużemu
            ],
        ),
        MorphRule(
            conditions: [GenderIs(Masculine), AnimacyIs(Animate), NumberIs(Singular), CaseIs(Accusative)],
            operations: [
                ReplaceSuffix { from: "y", to: "ego" },// duży kot → dużego kota
            ],
        ),
        MorphRule(
            conditions: [GenderIs(Masculine), AnimacyIs(Inanimate), NumberIs(Singular), CaseIs(Accusative)],
            operations: [],                            // duży dom → duży dom (ACC=NOM for inanimate)
        ),
        
        // Feminine
        MorphRule(
            conditions: [GenderIs(Feminine), NumberIs(Singular), CaseIs(Nominative)],
            operations: [
                ReplaceSuffix { from: "y", to: "a" },  // duży → duża
            ],
        ),
        MorphRule(
            conditions: [GenderIs(Feminine), NumberIs(Singular), CaseIs(Accusative)],
            operations: [
                ReplaceSuffix { from: "y", to: "ą" },  // duży → dużą
            ],
        ),
        
        // Neuter
        MorphRule(
            conditions: [GenderIs(Neuter), NumberIs(Singular), CaseIs(Nominative)],
            operations: [
                ReplaceSuffix { from: "y", to: "e" },  // duży → duże
            ],
        ),
        
        // ─── PLURAL ────────────────────────────────
        // Virile (masculine personal plural)
        MorphRule(
            conditions: [GenderIs(MasculinePersonal), NumberIs(Plural), CaseIs(Nominative)],
            operations: [
                ReplaceSuffix { from: "y", to: "y" },  // duży → duzi (with consonant shift: ż → z)
                ConsonantAlternate { from: "ż", to: "z" },
            ],
        ),
        // Non-virile plural
        MorphRule(
            conditions: [NumberIs(Plural), CaseIs(Nominative)],
            // non-virile: uses "e" ending
            operations: [
                ReplaceSuffix { from: "y", to: "e" },  // duży → duże
            ],
        ),
    ],
    exceptions: [],
)
```

## English Morphology

English morphology is simpler (analytic language) but still algorithmic:

### Verb: Regular "-ed"

```rust
// data/morphology/en/verb_paradigms.ron

Paradigm(
    name: "verb_regular",
    applies_to: Verb,
    rules: [
        // Present
        MorphRule(
            conditions: [TenseIs(Present), PersonIs(Third), NumberIs(Singular)],
            operations: [AddSuffix("s")],      // walk → walks
        ),
        MorphRule(
            conditions: [TenseIs(Present)],
            operations: [],                    // walk → walk (all other forms)
        ),
        
        // Past
        MorphRule(
            conditions: [TenseIs(Past)],
            operations: [AddSuffix("ed")],     // walk → walked
        ),
        
        // Present participle
        MorphRule(
            conditions: [AspectIs(Progressive)],
            operations: [AddSuffix("ing")],    // walk → walking
        ),
    ],
    exceptions: [
        // Spelling rules as exceptions
        MorphException(
            conditions: [TenseIs(Past), StemEndsWith("e")],
            override_suffix: "d",              // love → loved (not *"loveed")
        ),
        MorphException(
            conditions: [AspectIs(Progressive), StemEndsWith("e")],
            operations: [
                Truncate(1),                   // remove "e"
                AddSuffix("ing"),              // love → loving
            ],
        ),
        // CVC doubling: stop → stopped, stopping
        MorphException(
            conditions: [StemPattern(CVC_Short_Vowel)],
            // double final consonant before -ed, -ing
            operations: [DoubleFinalConsonant, AddSuffix("ed")],
        ),
    ],
)
```

### Noun: Plural

```rust
Paradigm(
    name: "noun_regular",
    applies_to: Noun,
    rules: [
        MorphRule(
            conditions: [NumberIs(Plural)],
            operations: [AddSuffix("s")],      // cat → cats
        ),
    ],
    exceptions: [
        MorphException(
            conditions: [NumberIs(Plural), StemEndsWith("s"), StemEndsWith("sh"), StemEndsWith("ch"), StemEndsWith("x")],
            override_suffix: "es",             // bus → buses, box → boxes
        ),
        MorphException(
            conditions: [NumberIs(Plural), StemEndsWith("y"), StemPrecedesY(Consonant)],
            operations: [
                ReplaceSuffix { from: "y", to: "ies" },  // city → cities
            ],
        ),
    ],
)
```

## Morphology in the Generation Pipeline

```
Interlingua: Frame::TRANSFER {
    agent: Entity{name:"Tomek", gender:M, number:Sg}
    theme: Entity{concept:APPLE, gender:N, number:Sg}
}
tense: PAST, aspect: PERFECTIVE

Generation steps:
│
├─→ 1. Select lemma for each entity from lexicon
│      agent → "Tomek" (proper noun, no declension)
│      theme → "jabłko" (noun, paradigm: noun_o)
│      predicate → "dać" (verb, paradigm: verb_dać_irreg)
│
├─→ 2. Determine case for each role (from GRAMMAR_CASES)
│      agent (NOM) → "Tomek" (masc personal, NOM.SG)
│      theme (ACC) → "jabłko" (neuter, ACC.SG = NOM form)
│
├─→ 3. Apply morphological rules
│      "Tomek" + NOM.SG → "Tomek"
│      "jabłko" + ACC.SG → "jabłko" (rule: neuter ACC = NOM)
│      "dać" + PAST.3SG.M → "dał"
│
├─→ 4. Agreement: adjectives match their noun
│      (no adjectives in this sentence)
│
└─→ Output: "Tomek dał jabłko"
```

## Phonological Sub-Rules

Some morphological operations trigger phonological changes:

### Polish Vowel Alternations

```rust
// These apply AFTER morphological operations as cleanup passes

PhonologicalRule(
    name: "o_to_ó",
    conditions: [StressOnSyllable(-2)],        // ó appears in stressed syllables
    operation: VowelAlternate { from: "o", to: "ó" },
    // Example: róg (NOM) → rogu (GEN) — the ó alternates with o
)

PhonologicalRule(
    name: "e_to_zero",
    conditions: [BeforeSuffix],                 // mobile e disappears
    operation: Truncate(1),
    // Example: pies (NOM) → psa (GEN) — the e disappears
)
```

### Polish Consonant Alternations

```rust
// Palatalization before front vowels (e, i)
PhonologicalRule(
    name: "palatalization",
    conditions: [BeforeVowel("e"), BeforeVowel("i")],
    operations: [
        ConsonantAlternate { from: "k", to: "c" },   // ręka → ręce
        ConsonantAlternate { from: "g", to: "dz" },  // noga → nodze
        ConsonantAlternate { from: "t", to: "ć" },   // kot → kocie (loc)
        ConsonantAlternate { from: "d", to: "dz" },  // gwiazda → gwieździe
        ConsonantAlternate { from: "n", to: "ń" },   // żona → żonie
    ],
)
```

These are stored in `data/morphology/pl/phonological_rules.ron` and applied as a post-processing step after all paradigm rules.

## Exception Philosophy

Exceptions exist but should be **minimized**. Before adding an exception:

1. Can a more specific rule cover it? (prefer rule over exception)
2. Is it truly irregular, or just a different paradigm class?
3. Can a phonological sub-rule handle it?

```
Truly irregular (needs exception):
  • "dać" → "daj" (imperative) — no rule predicts this
  • "iść" → "szedł" (past) — suppletive stem
  • "być" → all forms — fully irregular

Different paradigm class (NOT an exception):
  • "widzieć" follows "eć" paradigm, not "ać" — just a different class
  • "mięso" follows "o" paradigm — straightforward

Phonological rule (NOT an exception):
  • "pies" → "psa" — mobile e rule covers this
  • "ręka" → "ręce" — palatalization rule covers this
```

## Allomorphy

Allomorphs are variant forms of the same morpheme that occur in different environments. They are predictable from context.

### Types of Allomorphy

**1. Phonologically Conditioned Allomorphy**

The form is determined by the phonological environment.

```rust
pub enum AllomorphType {
    /// Different forms based on surrounding sounds
    Phonological {
        environment: PhonologicalEnvironment,
        form: String,
    },
}

pub enum PhonologicalEnvironment {
    BeforeVowel,
    BeforeConsonant,
    WordFinal,
    AfterNasal,
    AfterSibilant,
}
```

**Example: English plural -s**

```
PhonologicalEnvironment → Allomorph:
  After voiceless consonant → /s/  (cats /kæts/)
  After voiced consonant    → /z/  (dogs /dɒɡz/)
  After sibilant            → /ɪz/ (buses /bʌsɪz/)
```

**Example: Polish instrumental plural**

```
After hard consonant → -ami  (kotami)
After soft consonant → -mi   (końmi)
After -a           → -ami   (kotami)
```

**2. Morphologically Conditioned Allomorphy**

The form is determined by the morphological context (specific words or paradigms).

```rust
pub struct MorphologicalAllomorph {
    /// Which lexemes trigger this allomorph
    triggers: Vec<String>,
    /// The allomorphic form
    form: String,
}
```

**Example: Polish "ten" (this)**

```
Masculine: ten (ten kot)
Feminine:  ta (ta książka)
Neuter:    to (to jabłko)
Plural:    ci (ci studenci) / te (te książki)
```

These are not predictable by phonology — they're stored as allomorphs in the paradigm.

**3. Lexically Conditioned Allomorphy**

Specific words have unique allomorphs that must be listed.

```rust
pub struct LexicalAllomorph {
    /// The lexeme that has this allomorph
    lexeme: String,
    /// The allomorphic form
    form: String,
    /// Context (case, number, etc.)
    context: FeatureBundle,
}
```

**Example: Polish "człowiek" (person)**

```
Singular: człowiek (NOM), człowieka (GEN), człowiekowi (DAT)
Plural:   ludzie (NOM) — suppletive!
          ludzi (GEN)
          ludziom (DAT)
```

The plural stem "ludzi-" is completely different from singular "człowiek-". This is suppletion (see below).

## Suppletion

Suppletion occurs when different forms of a word come from **completely different historical roots**. These forms cannot be predicted by rules and must be listed explicitly.

### Representing Suppletion

```rust
pub struct SuppletiveParadigm {
    /// Base form (citation form)
    pub base: String,
    
    /// Suppletive stems for different contexts
    pub stems: Vec<SuppletiveStem>,
}

pub struct SuppletiveStem {
    /// When to use this stem
    pub conditions: Vec<Condition>,
    /// The suppletive stem
    pub stem: String,
}
```

### Common Suppletive Words (Polish)

**1. "iść" (to go) — verb suppletion**

```
Present: idę, idziesz, idzie (stem: id-)
Past:    szedłem, szedłaś, szedł (stem: szedł-)
Future:  pójdę, pójdziesz, pójdzie (stem: pójd-)
```

```rust
SuppletiveParadigm {
    base: "iść",
    stems: vec![
        SuppletiveStem {
            conditions: vec![TenseIs(Present)],
            stem: "id",
        },
        SuppletiveStem {
            conditions: vec![TenseIs(Past)],
            stem: "szedł",
        },
        SuppletiveStem {
            conditions: vec![TenseIs(Future)],
            stem: "pójd",
        },
    ],
}
```

**2. "być" (to be) — highly suppletive**

```
Present: jestem, jesteś, jest (stem: jest-)
Past:    byłem, byłaś, był (stem: by-)
Future:  będę, będziesz, będzie (stem: będ-)
```

**3. "dobry" (good) — adjective suppletion**

```
Positive:  dobry (good)
Comparative: lepszy (better) — different root!
Superlative: najlepszy (best)
```

```rust
SuppletiveParadigm {
    base: "dobry",
    stems: vec![
        SuppletiveStem {
            conditions: vec![DegreeIs(Positive)],
            stem: "dobr",
        },
        SuppletiveStem {
            conditions: vec![DegreeIs(Comparative)],
            stem: "leps",
        },
        SuppletiveStem {
            conditions: vec![DegreeIs(Superlative)],
            stem: "najleps",
        },
    ],
}
```

**4. "dużo" (much) — adverb suppletion**

```
Positive:  dużo (much)
Comparative: więcej (more) — different root!
Superlative: najwięcej (most)
```

### Common Suppletive Words (English)

| Base | Comparative | Superlative |
|------|-------------|-------------|
| good | better | best |
| bad | worse | worst |
| much/many | more | most |
| little | less | least |
| far | farther/further | farthest/furthest |

| Base | Past | Past Participle |
|------|------|-----------------|
| go | went | gone |
| be | was/were | been |
| do | did | done |
| have | had | had |

## Zero Morphology

Some grammatical categories are expressed by **no overt marking** — the form is identical to the base form. This is called zero morphology or null inflection.

### Zero Marking in Polish

**1. Neuter nouns: ACC = NOM**

```
jabłko (NOM) = jabłko (ACC)
dziecko (NOM) = dziecko (ACC)
```

```rust
MorphRule(
    conditions: [
        GenderIs(Neuter),
        CaseIs(Accusative),
        NumberIs(Singular),
    ],
    operations: [],  // No change!
)
```

**2. Inanimate masculine nouns: ACC = NOM**

```
dom (NOM) = dom (ACC)
kot (NOM) = kot (ACC)
```

```rust
MorphRule(
    conditions: [
        GenderIs(Masculine),
        AnimacyIs(Inanimate),
        CaseIs(Accusative),
        NumberIs(Singular),
    ],
    operations: [],  // No change!
)
```

**3. 3rd person singular neuter past: -ło**

```
czytać → czytało (it read)
```

The ending -ło is the overt marker, but for some verbs the stem doesn't change:

```
dać → dało (it gave) — stem "da-" unchanged
```

### Zero Marking in English

**1. Plural: zero for some nouns**

```
sheep (SG) = sheep (PL)
deer (SG) = deer (PL)
fish (SG) = fish (PL)
```

```rust
MorphRule(
    conditions: [
        LemmaIs("sheep"),  // or specific lexemes
        NumberIs(Plural),
    ],
    operations: [],  // No change!
)
```

**2. Past tense: zero for some verbs**

```
cut (PRES) = cut (PAST)
put (PRES) = put (PAST)
hit (PRES) = hit (PAST)
```

**3. 3rd person singular: zero for modals**

```
can (1sg) = can (3sg)
must (1sg) = must (3sg)
should (1sg) = should (3sg)
```

### Representing Zero Morphology

```rust
pub struct ZeroMorphRule {
    /// When zero marking applies
    pub conditions: Vec<Condition>,
    /// Explicit marker that this is zero morphology
    pub zero: bool,
}
```

Zero morphology is just a rule with no operations. It's important to document these cases explicitly so the system knows when NOT to apply other rules.

## Morphological Ambiguity

A single surface form can correspond to multiple analyses. The parser must disambiguate based on context.

### Common Ambiguities (Polish)

**1. Case ambiguity**

```
"jabłko" → NOM.SG or ACC.SG (neuter)
"książki" → GEN.SG or NOM.PL or ACC.PL (feminine)
"domu" → GEN.SG or LOC.SG (masculine)
```

**Resolution:** Use verb subcategorization and word order.

```
"Tomek dał jabłko Izie"
  → "dać" requires [agent:NOM, theme:ACC, recipient:DAT]
  → "jabłko" must be ACC (theme), not NOM (agent)
```

**2. Person/number ambiguity**

```
"czyta" → 3SG.PRES or 2SG.IMPERATIVE
"czytaj" → 2SG.IMPERATIVE (unambiguous)
```

**Resolution:** Use sentence type (statement vs command).

**3. Gender ambiguity**

```
"dał" → 3SG.PAST.M (he gave)
"dała" → 3SG.PAST.F (she gave)
"dało" → 3SG.PAST.N (it gave)
```

These are unambiguous, but pronouns can be ambiguous:

```
"jego" → GEN.SG.M or ACC.SG.M (his/him)
"jej" → GEN.SG.F or DAT.SG.F (her/to her)
```

**Resolution:** Use syntactic position and verb requirements.

### Ambiguity Resolution Pipeline

```rust
pub fn resolve_morphological_ambiguity(
    form: &str,
    candidates: Vec<MorphAnalysis>,
    context: &ParseContext,
) -> MorphAnalysis {
    // Strategy 1: Verb subcategorization
    if let Some(verb_subcat) = context.verb_subcategorization {
        let filtered = candidates.iter()
            .filter(|c| verb_subcat.accepts(c.case))
            .collect::<Vec<_>>();
        
        if filtered.len() == 1 {
            return filtered[0].clone();
        }
    }
    
    // Strategy 2: Agreement with adjacent words
    if let Some(adj) = context.adjacent_adjective {
        let filtered = candidates.iter()
            .filter(|c| c.agrees_with(&adj))
            .collect::<Vec<_>>();
        
        if filtered.len() == 1 {
            return filtered[0].clone();
        }
    }
    
    // Strategy 3: Word order heuristics
    if context.position == SentencePosition::PreVerbal {
        // Pre-verbal position tends to be subject (NOM)
        let nom_candidates = candidates.iter()
            .filter(|c| c.case == Case::Nominative)
            .collect::<Vec<_>>();
        
        if nom_candidates.len() == 1 {
            return nom_candidates[0].clone();
        }
    }
    
    // Strategy 4: Frequency (most common form)
    candidates.iter()
        .max_by_key(|c| c.frequency)
        .unwrap()
        .clone()
}
```

## Summary

Advanced morphology features:

1. **Allomorphy** — variant forms determined by phonological, morphological, or lexical context
2. **Suppletion** — completely different roots for different forms (go/went/gone, good/better/best)
3. **Zero morphology** — grammatical categories expressed by no overt marking (neuter ACC = NOM)
4. **Morphological ambiguity** — single form with multiple analyses, resolved by context

These features are represented in the paradigm system through:
- `Allomorph` types for variant forms
- `SuppletiveParadigm` for completely different stems
- Empty `operations` for zero morphology
- Disambiguation pipeline using verb subcat, agreement, word order, and frequency
